# Guía de bienvenida — issue #296

Documento de decisiones de producto en curso. No es todavía un brief de implementación.

## Decisiones acordadas

- Guía de configuración con acciones directas para usuarios actuales y futuros.
- Se muestra automáticamente en el primer acceso; puede omitirse con «Ahora no» y
  retomarse hasta completarla.
- Se completa al crear una cuenta y registrar el primer movimiento.
- Presupuestos, inversión e integraciones son siguientes pasos opcionales.
- Crear automáticamente categorías editables para usuarios nuevos:
  - Ingresos: Nómina, Otros ingresos.
  - Gastos: Vivienda, Alimentación, Transporte, Suministros, Salud, Ocio, Otros gastos.
  - Inversión: Inversión.
- No ampliar automáticamente las categorías de usuarios existentes.
- Tampoco ofrecer a usuarios existentes una acción para añadir las categorías sugeridas.
- Mostrar avisos cuando falte configuración necesaria, explicar el requisito y
  ofrecer una acción directa para resolverlo. Bloquear únicamente las acciones afectadas.
- Movimientos sin cuentas: aviso y acción «Crear cuenta»; bloquear el alta.
- Revisar otras páginas para identificar sus requisitos reales.
- Los avisos de requisitos pendientes se aplican a cualquier usuario.
- La omisión y el avance de la guía se guardan por usuario, compartidos entre dispositivos.
- Al desplegar esta funcionalidad, mostrar la guía una vez a todos los usuarios
  actuales, incluso si ya tienen cuentas y movimientos. No excluirlos por tener
  los hitos completos.
- Reconocer los hitos ya completados; si ambos están completos, mostrar «Entendido»
  para cerrar la bienvenida, sin exigir datos adicionales.
- Importar datos cuenta para completar los hitos si incluye cuenta y movimiento.
- Borrar datos tras completar la guía no la reabre automáticamente; los avisos
  siguen respondiendo a los requisitos que falten.

## Comprobación del código

- La inicialización explícita crea Ingresos y Gastos generales, sin cuentas ni
  categoría de inversión. El bootstrap puede devolver configuración nula.
- Movimientos y suscripciones necesitan cuenta; las reglas recurrentes también.
- Los movimientos de inversión y compras recurrentes necesitan cuenta. Los
  selectores actuales usan las cuentas disponibles sin exigir un tipo inversión.
- Presupuesto necesita categorías del tipo seleccionado, pero no cuentas.
- Patrimonio necesita alguna cuenta de efectivo, inversión o pasivo para tener
  saldos que editar; no necesita que existan los tres tipos.
- Objetivos permite definir metas sin cuentas ni movimientos.
- Aportes tiene avisos existentes de valoraciones, cuentas de liquidez e importes
  sin asignar. Estos avisos no equivalen todos a requisitos de configuración.
- Las integraciones tienen sus propios requisitos; no son necesarias para el
  registro manual de movimientos de inversión.

## Agent Brief

**Category:** enhancement

**Summary:** Guiar la configuración inicial y explicar los requisitos pendientes
de cada acción para usuarios actuales y futuros.

**Current behavior:** La inicialización explícita crea dos categorías básicas y
ninguna cuenta. Hay mensajes vacíos aislados, pero no una guía de configuración.
Distintos formularios permiten iniciar altas sin disponer de la cuenta necesaria.
Verificación estática de inicialización, stores y formularios; no se ha reproducido
el recorrido de un registro nuevo en navegador.

**Desired behavior:** Mostrar una bienvenida omisible al primer acceso tras el
despliegue a todos los usuarios actuales y al primer acceso de usuarios futuros.
Ofrecer acciones directas para crear una cuenta y registrar el primer movimiento.
Reconocer los hitos existentes, incluidos los obtenidos por importación. Si ambos
ya están completos, mostrar «Entendido» para cerrar la bienvenida. Recordar por
usuario su presentación, omisión y avance entre dispositivos; permitir retomarla
tras «Ahora no» hasta completarla. No reabrirla por borrar datos tras finalizarla.
Presupuestos, inversión e integraciones son siguientes pasos opcionales.

Crear automáticamente, solo para usuarios nuevos, categorías editables: Nómina y
Otros ingresos; Vivienda, Alimentación, Transporte, Suministros, Salud, Ocio y
Otros gastos; Inversión. Mantener intactas las categorías de usuarios actuales y
no ofrecerles una acción de añadir sugerencias. La inicialización repetida no
debe duplicar categorías ni alterar datos existentes.

Para cualquier usuario, mostrar mensajes que expliquen la configuración faltante
y ofrezcan una acción directa para resolverla. Bloquear únicamente las acciones
afectadas. Actualizar el aviso cuando se resuelva o vuelva a faltar el requisito.
Aplicar los requisitos reales, sin imponer otros nuevos:

- Movimientos, suscripciones, reglas recurrentes, movimientos de inversión y
  compras recurrentes: una cuenta disponible.
- Presupuesto: categorías del tipo seleccionado; no requiere cuentas.
- Patrimonio: alguna cuenta de efectivo, inversión o pasivo para editar saldos;
  no exigir los tres tipos.
- Objetivos: permitir definir metas sin cuentas ni movimientos.
- Aportes e integraciones: revisar y conservar sus requisitos específicos y los
  avisos existentes, distinguiendo advertencias de condiciones que bloquean una
  acción. Las integraciones no son requisito para operar manualmente.

**Key interfaces:**

- Configuración del usuario: estado duradero de bienvenida y omisión.
- Inicialización del espacio privado: categorías iniciales sin duplicados.
- Estado financiero: cuentas y movimientos determinan los hitos reales.
- Acciones de alta y navegación: acceso directo a resolver cada requisito,
  respetando los flujos existentes y el lenguaje visual v2.

**Acceptance criteria:**

- [ ] Un usuario existente ve una vez la bienvenida tras el despliegue, incluso
  con cuenta y movimiento; los hitos existentes aparecen completados.
- [ ] Un usuario futuro ve la guía al primer acceso y puede completar los dos hitos.
- [ ] «Ahora no» permite retomarla; omisión y avance se conservan entre dispositivos.
- [ ] Con los dos hitos previos completos, «Entendido» cierra la bienvenida sin
  exigir otra cuenta ni otro movimiento.
- [ ] Una importación puede completar los hitos; borrar datos tras finalizar no
  reabre automáticamente la guía.
- [ ] Los nuevos reciben las categorías acordadas sin duplicados; los existentes
  conservan las suyas sin acción de añadir sugerencias.
- [ ] Cada acción sin configuración necesaria muestra el requisito y una salida
  directa antes de abrir un formulario imposible de completar.
- [ ] Resolver el requisito habilita la acción; eliminarlo vuelve a activar el aviso.
- [ ] Presupuesto funciona sin cuentas y Objetivos permite definir metas sin datos.
- [ ] No se exige una integración ni un nuevo tipo de cuenta para inversión manual.
- [ ] Los avisos se aplican a usuarios actuales y futuros, independientemente de
  haber finalizado la guía.
- [ ] Verificar los recorridos relevantes, incluida bienvenida con y sin datos,
  omisión, importación y resolución de requisitos; ejecutar los checks del repositorio.

**Out of scope:**

- Tour de todas las pantallas mediante globos explicativos.
- Crear cuentas, saldos o movimientos ficticios.
- Cambiar categorías de usuarios actuales o sugerirles su ampliación.
- Obligar a configurar presupuestos, inversión o integraciones para completar la guía.
- Rediseñar pantallas completas o cambiar reglas financieras existentes.
