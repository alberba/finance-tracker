# APIs para precios de cartera — 2026-10-18

Comparativa acotada para la integración de precios de `finance-tracker`. El usuario no ha indicado
qué activos tiene ni qué bróker usa. Los datos de proveedor no sustituyen un precio ejecutable; en
la interfaz conviene indicar la hora del dato recibido y no llamar «tiempo real» a una respuesta
solo porque se haya consultado ahora.

## Límite de la investigación y criterio de frescura

Los fondos tradicionales tienen [valor liquidativo generalmente diario](https://www.cnmv.es/Portal/inversor/glosario?id=0&idlang=1&lang=es&term=Valor+liquidativo), con excepciones de menor frecuencia. No se debe prometer un precio negociable en tiempo real para ellos. Un ETF cotizado es un caso distinto.

Los precios publicados son en dólares; no se ha confirmado el importe final con impuestos para España.

Finnhub ofrece una API oficial de cotizaciones, pero la documentación/pricing accesible en esta
revisión no permitió confirmar de forma primaria el alcance vigente del nivel gratuito, su cuota,
licencia de uso ni qué mercados son live frente a delayed. La página de precios sí separa productos
de datos de Londres retrasados y niveles Euronext/Xetra de pago, pero no basta para recomendar el
free tier; queda fuera del comparativo hasta verificar esos términos directamente.

## Proyectos open source que sirven de referencia

- [`yahoo-finance2`](https://github.com/gadicc/yahoo-finance2): cliente TypeScript que corre en Node y soporta cotización e histórico. Su licencia MIT hace reutilizable la librería, mientras su propio README dice que el acceso es no oficial y sin garantías. Es técnicamente más directo que introducir Python/yfinance. `yfinance` sí declara `WebSocket`/`AsyncWebSocket` para streaming, pero es Python, usa Yahoo no oficial, se describe para investigación/educación/uso personal y remite expresamente a Yahoo para los derechos del dato. Para este repo no compensa montar un proceso Python solo por streaming; además, streaming no prueba que el feed sea cotización consolidada/live autorizada.
- [Ghostfolio](https://github.com/ghostfolio/ghostfolio): producto completo self-hosted TypeScript bajo AGPL-3.0. Su propio README describe cartera multi-plataforma de acciones, ETF y cripto, pero añade backend NestJS/PostgreSQL/Redis y front Angular, un despliegue entero. El API permite identificar activos con fuentes `YAHOO`, `COINGECKO` y `MANUAL`; la discusión de mantenedores dice que otras fuentes son experimentales. No es una dependencia ligera para añadir cotizaciones a finance-tracker. Sus fuentes de mercado tampoco evitan las condiciones del proveedor subyacente.
- [Portfolio Report / Portfolio Performance](https://help.portfolio-performance.info/en/how-to/downloading-historical-prices/portfolioperformance/): Portfolio Report era una fuente web de precios usada por la app Java de escritorio; el manual actual ofrece migración desde ella al proveedor integrado de Portfolio Performance. Ese proveedor actual requiere una cuenta gratuita Portfolio Performance ID y da precios históricos para más de 20 mercados europeos y grandes bolsas de EE. UU.; solo la suscripción pagada habilita cotizaciones retrasadas actuales, únicamente para valores de EE. UU. La app de referencia es EPL-1.0, no una API REST pequeña que podamos reutilizar. Leeway/PWP publica hoy una API relacionada: cotizaciones mundiales de acciones con retraso de 15–20 min, pero el paquete API publicado cuesta desde 69,95 €/mes y el WebSocket figura en beta privada; no encaja como coste incremental cero.
- [CCXT](https://github.com/ccxt/ccxt) es una librería MIT gratuita para integrar APIs de exchanges, incluidos datos públicos sin credenciales cuando el exchange los permite. Encaja para cripto, no para acciones o ETF; el precio corresponde al exchange y par consultados. Si solo necesitamos un exchange, también se puede integrar directamente el [canal público ticker de Kraken](https://docs.kraken.com/exchange/api-reference/spot-websocket-v2/ticker), que emite actualizaciones por operaciones o cambios del mejor precio comprador/vendedor. Esto ofrece un camino a streaming de cripto sin un agregador de pago; sigue sujeto a las condiciones y límites del exchange.

### Recomendación práctica para una integración OSS

Con el servidor existente, el camino incremental sería probar primero el adaptador Yahoo actual
con una pequeña matriz de símbolos; si se prioriza una implementación mantenida en TypeScript,
`yahoo-finance2` puede reemplazar código HTTP propio sin una dependencia de runtime pesada. Usarlo
con límites bajos, caché, manejo de 429/errores y timestamp original de mercado. Dejar explícita la
revisión de términos antes de habilitarlo como servicio para usuarios:
el código MIT no autoriza los datos. Para valores liquidativos/fondos, aceptar cotización diaria o
la frecuencia oficial del instrumento; para cotización consolidada/live multi-bolsa, no hay en esta
revisión una API OSS y gratuita verificada. No introducir Ghostfolio como dependencia ni un stack
aparte de Python/yfinance por el objetivo de bajo coste.

En el modelo del producto, separar **hora de consulta** de **hora del precio**. Guardar y devolver
`provider`, mercado/símbolo resuelto, moneda, timestamp del proveedor (si viene), tipo de dato
(EOD, delayed o live documentado) y timestamp de recuperación. Si el proveedor no expone una hora
de observación verificable o no documenta el retraso, mostrar «último dato recibido» o «cierre» y
no inferir frescura por el timestamp HTTP/local.

### Comprobación puntual de Yahoo (2026-10-18)

Se consultó desde el servidor el mismo endpoint chart usado por el adaptador actual, sin instalar
paquetes ni tocar el código. Respondió HTTP 200 para AAPL (`USD`, mercado `NMS`, timestamp de
mercado `2026-10-16T20:00:01Z`), VWCE.DE (`EUR`, `GER`, `2026-10-16T15:36:07Z`) y BTC-EUR
(`EUR`, `CCC`, `2026-10-18T18:25:47Z`). El 18 de octubre fue domingo: la consulta demuestra que
el endpoint funciona para esos tres símbolos y entrega hora del mercado, pero no prueba la demora
de la última operación ni que el feed bursátil sea live. No se registran aquí precios.

## Estado observado en finance-tracker

- `src/lib/server/market-data.ts` implementa Twelve Data, Yahoo y CoinGecko, con caché de 120 segundos por defecto. Tener el adaptador no demuestra que haya credenciales configuradas ni cobertura de la cartera del usuario.
- `src/composables/useLiveQuotes.ts` refresca al montar y cambiar instrumentos. El reloj compartido actualiza la antigüedad del dato; no solicita precios periódicamente.
- El conector CoinGecko no solicita `include_last_updated_at`; la normalización puede usar la hora local como timestamp. Habría que distinguir hora del precio y hora de consulta.
- `src/stores/market.ts` documenta que las mutaciones de instrumentos no están conectadas a los comandos de sync v2. Debe resolverse para mantener la configuración entre dispositivos.
- `src/domain/investment/valuation.ts` admite tipos de cambio, pero el store llama sin ellos. Para sumar posiciones en monedas distintas hay que suministrarlos; el fallback actual es 1.

La propuesta inicial es validar 2–3 tickers o ISIN reales y decidir proveedor por clase de activo, con actualización mientras la vista esté abierta, cuotas controladas, hora del dato visible y valoración en EUR. Actualizar precios no importa compras o ventas del bróker: esa sincronización necesita una integración aparte. No se ha cambiado código ni configuración en esta investigación.
